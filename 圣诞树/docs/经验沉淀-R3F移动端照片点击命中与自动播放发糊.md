# 经验沉淀：R3F 移动端照片“难点击/命中不稳定”与自动播放放大发糊

## 背景
圣诞树照片在**移动端**使用 `@react-three/drei/Html` 直接渲染 `<img>`（避免纹理加载开销），但出现：

- **照片很难点中**：必须非常精准才能弹出大图
- **自动播放放得太大**：图片被放大后明显发糊

## 根因分析（高频踩坑点）
- **Raycast 命中被“树本体粒子/灯串”抢走**  
  `Points` / `InstancedMesh` 数量大、覆盖范围广，点击时 Raycaster 更容易先命中这些对象，导致照片所在的 mesh 没拿到事件。
- **Html 叠加层不可交互**  
  为了让事件落到 WebGL 画布，我们通常会对 `<Html>` 设置 `pointerEvents: 'none'`，这会让“看得到的图片”本身不参与命中。
- **重要细节：`Html` 的 `pointerEvents: none` 不一定会让子元素也“穿透”**  
  在一些浏览器里，`<Html style={{ pointerEvents: 'none' }}>` 的子节点（如 `div/img`）仍可能默认 `pointer-events: auto` 并吃掉点击，导致“点在图片上没反应，点到图片外/下方才行”。  
  处理方式：对 **子元素也显式设置 `pointerEvents: 'none'`**，或反过来让 Html 自己可点并在 DOM 层处理打开逻辑。
- **HTML 图片的像素尺寸较小**  
  移动端 `<img width=80px>` 在相机推进（自动播放）时会被 3D transform 等比放大到大尺寸，必然出现“放大发糊”。

## 解决方案（推荐组合）
### 方案 A：加大照片的透明命中面（简单但不一定彻底）
- 在每张照片前放一个透明 `planeGeometry`，扩大可点范围。
- 优点：实现快、直观
- 缺点：仍可能被 Points/灯串抢占命中，体验不稳定

### 方案 B：移动端启用“模糊命中”（推荐）
- 在树根 `group` 上挂 `onClick`，点击到树任意位置时：
  - 将每张照片的世界坐标投影到 NDC（`Vector3.project(camera)`）
  - 用 `event.pointer`（NDC）计算屏幕距离
  - 取最近且小于阈值的照片作为命中结果
- 优点：**不依赖 raycast 命中照片 mesh**，能显著提升“好点”的手感
- 建议：只在 `state === 'FORMED'` 启用，避免 CHAOS 状态误触

## 自动播放放大发糊的处理
- 移动端自动播放不要把相机推得太近（`closeDist` 取更大值），让照片在屏幕上保持中等尺寸即可。
- 如果仍不清晰：考虑在自动播放时提高 `<img>` 的像素宽度或动态调整 `distanceFactor`（但会带来更多内存/带宽开销）。

## 落地要点（本项目）
- **移动端照片点击**：使用“模糊命中”兜底（阈值可按体验微调，如 `0.18 ~ 0.25`）
- **自动播放**：移动端 `closeDist` 增大，避免 Html 图片被放到发糊
