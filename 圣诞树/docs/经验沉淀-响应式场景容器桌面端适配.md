# 经验沉淀：响应式场景容器在桌面端多分辨率的适配

## 问题场景

宠物模块的 SVG 场景在移动端表现良好（横向滚动全景），但在桌面端 1K/2K/4K 屏幕上，场景被放大裁切，边缘元素（台灯、小黄鸭等）不可见。

## 根因分析

布局采用**高度驱动**策略：场景容器 `h-full` + `aspectRatio: 16/9` + `width: auto`，高度填满后计算宽度。在高分辨率桌面端：

- 容器 `max-w-[1000px]` 限制了可视宽度
- 场景高度很大 → 计算出的宽度远超 1000px → 溢出 + 需要横滚
- 用户看到的是"放大"的局部场景

**数值示例：** 1080p 屏幕场景区高度约 700px → 宽度 = 700 × 16/9 ≈ 1244px > 1000px

## 解决方案：桌面端 contain-fit

通过 Tailwind 响应式断点（`lg:` = 1024px+），在桌面端切换为 **contain-fit** 模式：

### 核心改动

| 层级 | 移动端（< 1024px） | 桌面端（≥ 1024px） |
|------|---------------------|---------------------|
| 主容器 | `max-w-[1000px] px-6` | `max-w-none px-[3vw]` |
| 滚动容器 | `overflow-x-auto snap-x` | `overflow-x-hidden snap-none` |
| 内层包装 | `w-max` (由内容撑开) | `w-full items-center` (居中) |
| 场景盒子 | `h-full, width: auto` | `w-full, h-auto, max-h-full` |

### CSS 关键机制 — Container Query 精确 contain-fit

**失败方案（不可靠）：** `width: 100%; max-height: 100%; aspect-ratio: 16/9;` — 在 flexbox 中 `width: 100%` 是定值约束，`max-height` 裁切高度后宽度不会跟着调整，导致比例破坏，SVG `slice` 模式裁切内容。

**正确方案：用 Container Query 单位精确计算**

```css
@media (min-width: 1024px) {
  .pet-scene-wrapper {
    container-type: size; /* 声明为尺寸容器 */
  }
  .pet-scene-box {
    /* 取"容器宽度"和"容器高度×16/9"中较小的值 */
    width: min(100cqw, calc(100cqh * 16 / 9));
    height: auto; /* 由 aspect-ratio: 16/9 从宽度计算 */
  }
}
```

数学推导：
- 若容器宽高比 > 16:9（宽屏）→ `100cqh * 16/9 < 100cqw` → 取高度驱动的宽度
- 若容器宽高比 < 16:9（窄屏）→ `100cqw < 100cqh * 16/9` → 取容器宽度
- 无论哪种情况，配合 `aspect-ratio: 16/9`，场景始终完整显示且不溢出

## 适用场景

- 任何固定宽高比的"画布"式 UI（游戏场景、视频播放器、画板）
- 需要同时适配移动端全屏和桌面端多分辨率的布局
- SVG viewBox 场景在不同屏幕尺寸下的完整展示

## 注意事项

1. CSS Container Query（`cqw`/`cqh`）需要 Chrome 105+, Firefox 110+, Safari 16+
2. **踩坑：** `aspect-ratio` + `max-height` 在 flexbox 中不可靠 — `width: 100%` 是定值，`max-height` 裁切后 `aspect-ratio` 无法回溯调整宽度
2. HUD 等非场景元素需要独立的 `max-width` 约束，防止在超宽屏上过度拉伸
3. SVG 的 `preserveAspectRatio="xMidYMid slice"` 在容器比例与 viewBox 匹配时等价于 `meet`，无需修改
4. 移动端保留横向滚动的全景体验，通过 `lg:` 断点精确区分两种模式
